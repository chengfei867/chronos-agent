3. **Designed the discriminated union (registry.ts)** — added two new
   exports without breaking the existing string contract:
   ```ts
   export type StructuredPayload =
     | { kind: "text"; text: string }
     | { kind: "tool_use"; name?: string; toolUseId?: string;
         input: Record<string, unknown> }
     | { kind: "tool_result"; content: string; isError?: boolean;
         toolUseId?: string }
     | { kind: "json"; value: unknown };
   export type SectionPayload = string | StructuredPayload;
   ```
   `FormattedSection.payload` widens from `string` → `SectionPayload`.
   This is opt-in per section: legacy string payloads (default, langgraph,
   header, extras) keep the `<pre>` rendering path; only the per-block
   sections from `anthropic_agents` use the structured branch. The
   `formatted.raw` "Show raw JSON" fallback is unchanged (still a single
   pretty-printed string).

4. **`buildBlockPayload(block)` helper in anthropic_agents.ts** — pure,
   shape-defensive function that branches on `block.type`:
   - `text` → `{ kind: 'text', text: block.text }` (or `kind:'json'`
     if `text` is missing).
   - `tool_use` → `{ kind: 'tool_use', name, toolUseId: block.id,
     input }` with non-object `input` coerced to `{}`.
   - `tool_result` → `{ kind: 'tool_result', content, isError, toolUseId }`
     where `content` normalises both string and `[{type:'text',text:...}]`
     list-of-chunks SDK conventions into a single string.
   - any other type → `{ kind: 'json', value: block }` (legacy fall-through).
   Each branch is shape-defensive; the registry's outer `try/catch`
   (R93 F-2 safety net) is preserved as the last line of defence.
   Wired in via the existing `blocks.forEach(...)` loop — only the
   `payload:` line changes.

5. **`renderPayload(payload)` switch in StatePanel.tsx** — switches on
   `typeof payload === 'string'` first (cheap guard), then on
   `payload.kind`:

   - `tool_use` → `<Tag color="purple">tool_use</Tag>` + tool name +
     `<Descriptions size="small" column={1} bordered>` of input keys.
   - `tool_result` → `<Tag color="cyan">tool_result</Tag>` (+ red `error`

   - `json` (and `default`) → existing `<pre>` with `safeStringify(value)`.
   The existing `<Collapse>` items stay; only the `children:` slot
   changes from a hardcoded `<pre>` to `renderPayload(section.payload)`.

## Decisions

- **D1 (payload widening, not replacement).** I chose `SectionPayload =
  string | StructuredPayload` over a clean-slate replacement
  (`payload: StructuredPayload`-only). The reason is that langgraph, default,
  header, and extras sections do not benefit from shape-aware rendering —
  forcing them through `{ kind: 'json', value }` would have meant rewriting
  three files for zero UX delta and pushing every adapter to know about the
  union shape. The TS narrowing in `renderPayload` is one extra
  `typeof === 'string'` check per section; cost is negligible and the
  rest of the codebase keeps its existing string-pretty contract.

- **D2 (no fresh ADR).** Slice 3 is squarely inside ADR-027 §2 slice 3;
  the discriminated union is an internal representation refinement
  (frontend-only, not a recorded contract), so no new ADR is needed.
  ADR-027 stays Accepted. Per R57 in-place rule, if a NEW ADR were
  introduced (e.g. to formalise a rendered-payload schema for future
  back-end deep-links), it'd start Draft and be promoted post-merge in
  the same diff. Not needed here.

- **D3 (no new spike, smoke harness instead).** CONTEXT §6 explicitly
  authorised "no new spike strictly needed" since slice 3's data-contract
  surface area is empty. I still wrote a Node+tsx smoke harness to give
  the impl commit empirical "the function does the right thing" coverage
  without dragging in vitest / RTL setup (which is out of slice 3 scope).
  The harness is checked in under `frontend/scripts/` so future rounds
  can re-run it as a regression check.

- **D4 (i18n key count: 6 vs the 4 estimated).** CONTEXT estimated 4 keys
  (`textBlock, toolUseBlock, toolResultBlock, toolError`); I shipped 6
  (added `textBlockEmpty, toolUseEmpty, toolResultEmpty`). The empty
  variants are user-visible placeholder strings — hard-coding them would
  break the bilingual rule under R46-A. I dropped `textBlock` as a
  user-visible label entirely (the section title `Block 0 — TextBlock`
  is already shown by the existing label/subLabel structure, no extra
  i18n needed). Net delta: +2 keys vs estimate.

- **D5 (Optional ε bundled, not deferred).** With slice 3 finishing in
  ~1/3 of the slot budget, I judged the 1-file `git mv` filler safer to
  bundle now than to carry forward another round. The R93 drift list
  shrinks by 1.

## Findings / lessons

- **F-1 (`tsx` is auto-installable for one-shot harnesses).** `npx tsx`
  pulled the package transparently and ran the harness against a TS
  source file with no separate compile step. Useful pattern for future
  one-shot frontend probes that don't want a vitest setup. Logged into
  smoke harness so future rounds know they can re-run with just
  `node frontend/scripts/r94-slice3-smoke.mjs`.

- **F-2 (existing `safeStringify` re-export from `default.ts`).**
  `StatePanel.tsx` now imports `safeStringify` from
  `../format/adapters/default` for the `kind:'json'` and tool_use
  non-string-value rendering paths. This is the only cross-component
  use; it's a legitimate re-use of a pure function, not a circular
  import (default.ts imports nothing from components). Frontend
  one-way-import contract preserved.

- **F-3 (slice 3 came in well under the 1-slot estimate).** The
  StructuredPayload design + `buildBlockPayload` helper + `renderPayload`
  switch landed in roughly half the expected effort — the main
  underpinning was already in place from R92 (Replay UI scaffolding) and
  R93 (registry + StatePanel skeleton). This validates the slicing
  decision in ADR-027: each slice ships standalone, the next slice
  inherits ground truth from the previous one.
