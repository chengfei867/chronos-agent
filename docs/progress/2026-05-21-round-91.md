## §4 — Findings

### F-1: A2 close-out chain length is now 11 (project-history high)

R48-A → R51 → R52 → R53 → R59 → R63 → R65 → R67 → R70 → R72 → R90 → **R91** = 11 consecutive A2 close-outs across 43 rounds (R48-A → R91 = 43 spans). The structural-constant hypothesis is now grade-A++ (was A+ at R72 confirmation): A2 close-out is a **structural-constant** of cron-slot rounds that ship ADR + survey/scaffold + cross-doc-references + close-out, regardless of feature area (Arc A / Arc B / Arc C planning) or round-type (impl / research / planning). **Codify into the skill**: when scheduling any round that ships ≥2 large md artifacts + ≥1 ADR + cross-references between them, **pre-budget 2 slots** by default and put the close-out (CHANGELOG + CONTEXT + progress doc + commit + push) in slot-2.

### F-2: R90's commit message surface is the new project standard

R90's `745d895` commit message is exemplary in three ways and should be a template:

1. **Names the failure mode explicitly** — "R89 cron slot authored 5 artifacts but exhausted its tool-call budget" — turning a one-line subject into self-documenting recovery context.
2. **Cites the skill name** — "per `cron-slot-handoff-recovery` skill (partial-execution variant — gate evidence intact, ceremony incomplete)" — gives future archaeologists a search anchor.
3. **Includes the 60-second diagnostic output** in the body — "Diagnostic at R90 slot start (BJT 09:54): All 5 R90 hard-prereqs green: …" — enables future agents to verify the recovery's assumptions without re-running the diagnostic.

This is the first A2 close-out commit in the chain to embed the diagnostic surface directly in the message body. **Adopt as standard for all future A2 close-out commits.**

### F-3: A2-of-A2 cascade ("dual close-out per slot") is a real failure shape

R90 attempted two close-outs in one slot: first close-out R89's WIP (succeeded at commit `745d895`), then start its own scheduled Option α work (succeeded artifact-wise but failed close-out). This is a NEW shape vs. prior chain entries — earlier rounds inherited ONE WIP and either committed it cleanly or got stuck in cleanup; R90 inherited one WIP, finished it cleanly, AND tried to ship a fresh round on the same budget.

**Lesson**: even if slot-1 successfully ships an inherited close-out commit, that close-out itself burns ~7-10 calls (status + verify + add + diff-check + commit + push + QQ). The remaining budget — typically ~30-35 calls — is **insufficient to also research + write + cross-reference 3 substantial md artifacts on Phase 5 arc selection**. R90 spent ~40+ calls on the research/ADR/roadmap edits and then ran out before its own close-out.

**Codification candidate for the skill**: when slot starts inheriting close-out work, do NOT plan a second new round in the same slot. Land the close-out, write a "next slot picks up R<N>" message, ship the QQ report, end the round. The next cron slot has a full fresh budget for the new work.

### F-4: Roadmap §Phase 5 stub replacement worked first try (R90 finding)

R90 used a single `patch` to replace the 3-line "Phase 5+ — v1.0 and Beyond (Vague on purpose)" stub with a 33-line committed charter. The patch's `old_string` was the entire stub and was unique. **Confirmation**: when replacing intentionally-vague placeholder text, the replacement always has a unique anchor (the placeholder phrase itself, e.g. "Vague on purpose"), so single-patch replacement is the right tool.
