## §2 Diagnostic — was this WIP safe to ship?

The cron-slot-handoff-recovery skill mandates **dynamic-string dependency
audit** before adopting inherited frontend WIP (R46-A trap). I ran the audit:

### A. i18n key resolution (R46-A trap pre-emption)

Grep extracted all `t("…")` keys used in `Replay.tsx` + `PlaybackTimeline.tsx`:

```text
t("replay.back")        t("replay.errorTitle")  t("replay.kbdHint")
t("replay.empty")       t("replay.model")       t("replay.stateAfter")
t("replay.stepBack")    t("replay.stepForward") t("replay.stepOf")
t("replay.title")       t("replay.tool")
t("tree.pause")         t("tree.play")          t("tree.reset")
```

Plus the templated `t(\`nodeKind.${activeNode.kind}\`, { defaultValue: kind })`
which has a built-in fallback so it can't fail.

Cross-checked against `frontend/src/i18n/en.ts` and `zh.ts`:

- All 11 `replay.*` keys defined in BOTH locales (matches the diff's +13/+13
  additions: 11 keys + 1 opening + 1 closing line per locale).
- `tree.play`, `tree.pause`, `tree.reset` were pre-existing keys (R37 timeline
  controls), reused without modification.
- `nodeKind.<kind>` block was pre-existing (TreeView legend).

**Verdict**: zero R46-A risk. Every dynamic-string lookup in the new code has a
defined key in both locales, with the templated kind lookup additionally
guarded by `defaultValue`.

### B. Hash-route ordering trap

`parseHash` in `App.tsx` was modified to match `/runs/<id>/replay` before
`/runs/<id>`. Verified the regex order: `replayMatch` is checked BEFORE the
generic `m = h.match(/^\/runs\/([^/]+)$/)`. Without this order, the more
permissive tree route would swallow `/runs/abc/replay` (matching `abc/replay`
as the runId), producing a TreeView mounted with a slash-containing runId and
404'ing the API call. Order is correct.

### C. AppHeader RouteName widening (caught by `tsc -b`)

First gate run surfaced a TS2322 error: `App.tsx` passes `route.name` as
`currentRoute` to `<AppHeader>`, and `AppHeader.tsx` had
`type RouteName = "landing" | "runs" | "tree" | "diff"` — missing `"replay"`.
Widened the union to include `"replay"`. The header doesn't render anything
route-specific for replay (no nav highlight, no breadcrumb), so this is purely
a type widening — no rendering change.

This is a **secondary-file-not-touched-by-prior-slot** trap: the prior slot
correctly added `"replay"` to App.tsx's `Route` union but missed the parallel
`RouteName` union in AppHeader. `tsc -b` catches it cleanly; runtime would have
been fine anyway because TypeScript erases unions at runtime. Lesson recorded
for future Replay-style multi-file route additions.
