## 1 · What I built

### 1.1 `tests/test_golden_fixtures.py` — parametrised shim

- **Discovery**: scans `tests/golden/<adapter>/<scenario>/` for any directory
  containing both `envelopes.jsonl` *and* `expected_run.json`. Includes the
  R102 `_skeleton/` fixture (real verifiable, not a placeholder).
- **Sentinel test** (`test_no_asymmetric_golden_fixtures`): fails loudly
  if a directory contains exactly one of the two required files.
  Defends against half-recorded / half-deleted state.
- **Parametrised test** (`test_chronos_verify_golden_exits_zero_for_committed_fixture`):
  for each fixture pair, invokes `chronos verify-golden` via
  `subprocess.run` and asserts exit 0 — full Typer-wrapped exit-code
  surface end-to-end.
- **Empty discovery**: returns `pytest.skip(...)` (R94 trap defence —
  *don't* pass-empty either; the sentinel covers half-broken state).
- **CLI invocation**: prefers `chronos` console script on PATH;
  falls back to `[sys.executable, "-c", "from chronos.cli import app; app()"]`
  for robustness across uv / activated venv / bare invocation.
- Marker: `@pytest.mark.golden` (registered in `pyproject.toml` since
  `--strict-markers` is on).

## 2 · Decisions

### D-106-1 — synthetic deterministic `run_id`

Both R105 and R106 plans were ambiguous about *where* the shim should
read `run_id` from when feeding `chronos verify-golden`. Inspection of
`src/chronos/golden/projection.py` confirms the projection **strips**
`run_id` (it's not part of the 8-key contract). Neither
`envelopes.jsonl` nor `expected_run.json` carries one in `_skeleton/`.

→ The shim does **not** need a `run_id` at all: `chronos verify-golden`
takes a fixture *directory*, replays the envelopes through the
in-process adapter, projects, and diffs against `expected_run.json`.
The `run_id` is internal to the replay.

This resolved a phantom blocker — no code change needed beyond writing
the shim correctly.

### D-106-2 — subprocess over `typer.testing.CliRunner`

R106 plan explicitly calls for full Typer-wrapped exit-code surface
end-to-end. `subprocess.run` exercises the installed console script
exactly as a CI runner / human would. CliRunner would short-circuit
the entry-point shim.

### D-106-3 — tight matrix on golden-verify.yml

Python 3.11 only. The wider 3.11+3.12 matrix lives in `ci.yml`.
Rationale: the contract gate is a *correctness* check, not a portability
check. Keep it fast and focused — if it's red, the contract is broken
on *any* Python.

### D-106-4 — asymmetric dirs = test failure, not skip

If a fixture dir has only `envelopes.jsonl` *or* only
`expected_run.json` (botched record / partial delete), the sentinel
test fails. R94 trap says *empty fixtures* should skip (covered);
*half-broken fixtures* must scream.
