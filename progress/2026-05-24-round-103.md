## Decisions / ADR posture

- **No ADR amendment needed.** ADR-028 §4 already specified slot-2 Option A
  as "land at R102 once spec stabilises" — R103 is the deferred execution,
  not a direction change. The R57 in-place rule applies only when ADR
  *content* changes; here, the plan was followed.
- **`__all__` re-export pattern at the module level** of `capture_anthropic_agents.py`:
  the unit-test harness loads the driver via
  `importlib.util.spec_from_file_location` and reaches into module attributes
  by name (`driver.project_to_golden`, `driver._canonicalise`, etc.). Plain
  imports from `chronos.golden` already bind those attributes at the driver
  module scope, but we set `__all__` explicitly to make the contract visible
  and to keep the test surface stable if someone later swaps the imports.
- **Underscore-prefixed names re-exported intentionally.** `_SECRET_PATTERNS`,
  `_canonicalise`, `_RUN_SUMMARY_KEYS`, `_GOLDEN_SCHEMA` are all consumed by
  sibling modules (spike19, the capture driver, the unit tests). The leading
  underscore signals "internal to the golden contract", not "private to this
  one file" — they're public to the chronos package, private to anything
  outside it. This matches the convention already used in
  `chronos.core._utils` (etc.).
- **Kept `test_capture_expected_run_byte_equality_with_spike_projection`.**
  It uses `driver` + `spike` fixtures, both of which now reach the same
  underlying `chronos.golden` impl — so the assertion is a tautology in the
  helper layer. But the test still exercises the full
  `capture_run(store, run_id, out_dir)` pipeline (DB read → projection →
  sanitiser → file write → re-read). It's an *integration* check on the
  capture driver's plumbing, not a helper-byte-parity pin. Worth keeping.

**Slot 3 (Arc D slice 3) — `chronos verify-golden` CLI**:

The capture side is done (R101 driver + R103 hoist). The next slot owns the
**read** side: a CLI subcommand that takes a fixture directory + a recorded
or replayed Run, projects via `chronos.golden.project_to_golden`, sanitises
via `chronos.golden.sanitise_capture` at LOAD time (the "suspenders" layer
per ADR-028 §4 — the capture driver is the "belt"), and asserts byte-equality
against `expected_run.json`. Failure modes:

1. **Mismatch** — print a unified diff of canonical JSON.
2. **Sanitiser hit at load** — fail with "secret in fixture, please re-record"
   (this means the belt was bypassed, e.g. the fixture predates R101).
3. **Missing `expected_run.json`** — fail with a hint pointing to
   `scripts/capture/capture_anthropic_agents.py`.

  no helper duplication this time, the package is the single home.

  modes + happy path. Fixture corpus reuses `tests/golden/_skeleton/` for
  the happy path; mismatched/secret-laden corpses synthesised in `tmp_path`.
- Update `docs/golden-trace-format.md` v0 with a "Verifier contract" section.
- (Defer) integrating verify-golden into CI is for R105 — the CLI must exist
  first.
