## Scope

Add a brand-new top-level verb `chronos doctor` that prints a one-shot environment health check covering Python version, package version, SQLite, `chronos.db`, examples directory, and the five optional extras. Read-only by contract — must never mutate state, never install anything, never touch the network. Designed for two use cases: (a) the first command a new user runs after `pip install chronos-agent` to confirm their environment is sound, (b) the triage prompt for support threads ("paste your `chronos doctor` output").

## Key decisions (上墙)

- **D-110-1 — exit-code policy: warnings never fail, only ❌ produces exit 1.** Rationale: a fresh install with no `chronos.db` is a *legitimate* state — the user just typed `pip install chronos-agent` and hasn't run `quickstart` yet. Failing on that would make `doctor` un-usable as the on-ramp's first command. Optional extras absent = ⚠️ for the same reason — they're optional by definition. Real ❌ surfaces are: Python < 3.11 (the package literally won't install on older Pythons, but better to catch a `pyenv` mismatch loudly), DB present-but-corrupt, DB schema major mismatch (would explode the user's next CLI call anyway).
- **D-110-2 — Free-function form `doctor_command(*, db, console, open_store_fn=None, examples_root=None) -> int`.** Same factoring as `quickstart_command` and `replay_command`. Lets unit tests inject a `Console(file=StringIO())` for output capture and a fake `open_store_fn` to deterministically surface I/O errors (the schema-mismatch test does exactly this).
- **D-110-3 — Rich label escaping with a hand-rolled `_escape_label()` helper, NOT `rich.markup.escape`.** Labels in this verb literally contain `[web]`, `[langgraph]`, `[anthropic_agents]`, etc. Rich would otherwise interpret those as style tags and silently delete them. `_escape_label` replaces `[` with `\[` (single character → two-char escape) and the row-print loop computes column padding on the raw width *before* escaping so columns still align — using `rich.markup.escape` would have given correct rendering but variable-width padding would drift. Hand-rolled keeps one-line code path and is the same trick used in `verify_golden.py` for the secret-detected output.
- **D-110-4 — Optional extra detection via `importlib.import_module(probe)` not `importlib.util.find_spec`.** `find_spec` returns truthy for *namespace packages* even when no submodule is installed, which would falsely report extras as present. `import_module` actually executes the package init, which is the same code path that `from langgraph import …` etc. would hit at runtime, so `doctor`'s "installed" verdict matches the verdict the rest of `chronos` would deliver. Caught by the missing-extra test (the test would have failed silently with `find_spec`).
- **D-110-5 — `_check_optional_extras` resolves version via `getattr(mod, "__version__", None)` then falls back to `importlib.metadata.version(probe.replace("_", "-"))`**. Two layers because: `crewai` exposes `__version__` directly, but `anthropic_agents` (the SDK) does not, only the dist-info package metadata records it. Both layers are wrapped in their respective exception types so a partial-install (rare but possible during user `uv pip install`) shows version `?` rather than crashing the whole `doctor` invocation. Defensive `# pragma: no cover` on the inner `PackageNotFoundError` because both layers failing would be a broken install where `doctor` is the least of the user's problems.
- **D-110-6 — Schema-version check uses major-only compatibility, delegating to `SqliteStore.open()`.** `SqliteStore.open()` already raises on major mismatch (since R30 it's the contract), so `_check_database` doesn't reimplement the version-parsing logic — it just catches the exception and surfaces it as a ❌ row. Keeps doctor's source code small, and means doctor's verdict and the "real" CLI verb's verdict on the same DB are always identical.

## Pitfalls caught during implementation

- **R45-A test-ratchet trap**: `tests/unit/test_cli.py::test_cli_help_default` asserts only on `"time-travel"` substring, NOT on verb count, so registering a 12th top-level verb is safe. Verified pre-modification by running `pytest -k cli_help` (29/29 GREEN before *and* after the registration).
- **`info()` streak counter**: was R52→R109 = 57; bumped to R52→R110 = 58 in the same edit that adds `doctor` to the commands list, so the `test_cli_info` assertion on the phase string ("phase 6") passes unchanged.
- **Rich markup label-eating**: caught during the in-tmpdir smoke run — `Extra: [web]` rendered as `Extra:` because Rich consumed `[web]` as a (non-existent) style tag. Fixed via `_escape_label` + raw-width column padding (D-110-3).
- **Schema-mismatch test was ambitious about the error path**: after writing `'99.0.0'` into `schema_info`, `SqliteStore.open()` raises *before* doctor's check_database can read the row, so the row reports "failed to open" not "schema mismatch" — the test asserts on `"schema" in out.lower() or "open" in out.lower()` to accept either path, and the ❌+exit-1 contract holds either way.
