### A. R118 deferred #2: TreeView Score Badge (前端, ~80 LOC TSX + 1 行 i18n × 2 locale + dist rebuild)

#### 改动清单

- **`frontend/src/api.ts`** (+12 LOC): 新增 `fetchEvaluations(runId)` helper, 调 `GET /runs/{id}/evaluations` (R115 ship 的 endpoint), 返回 `{ evaluations, count }`。Evaluation 类型已经在 R115 加进 `types.ts`, 这里只是导出 client wrapper。
- **`frontend/src/pages/TreeView.tsx`** (+62 LOC, -3 LOC): 三处改动:
  - `import` 加 `fetchEvaluations` + `Evaluation` 类型 (后者从 `../types`)。
  - `InnerTree` 函数签名加 `evaluations: Evaluation[]` prop, 在 Run Info card 的 `Statistics Row` 末尾条件渲染一个 `<Col span={24}>` 包裹的 `<Statistic>` 卡: `title` 是 \"Eval score\" + 紫色 evaluator-name `<Tag>` (purple, fontSize=10), `value` 是 latest evaluator 的 score (整数或 `.toFixed(4)`) 或 `passed` 布尔渲染成 `✓` (绿) / `✗` (红); `<Tooltip>` 包外, title 是 `${evaluator_name}: ${rationale}` (如有 rationale) 或纯 evaluator name。
  - 默认导出函数 `TreeView({ runId })` 加 `evaluations` state 默认 `[]`, 在 effect 里 `Promise.all([fetchRun, fetchTree])` 之外**独立**调 `fetchEvaluations(runId)` (failure 是非致命的 — 老 run 可能没 evaluator 跑过, 或 evaluations 表是空的, 不能挂掉树渲染); 错误吞掉, score badge 就不显示。
- **`frontend/src/i18n/en.ts`** (+1 LOC): `tree.evalScore = \"Eval score\"`。
- **`frontend/src/i18n/zh.ts`** (+1 LOC): `tree.evalScore = \"评估分数\"`。
- **`frontend/dist/`**: vite build 输出: `index-d3JEOd4V.js` 删 / `index-B0f7fjX1.js` 加 / `index.html` 引用替换。

#### 设计决策

- **D-121-1: \"Latest\" = `evaluations[evaluations.length - 1]`.** R115 backend `GET /runs/{id}/evaluations` 返回的 array 是按 `created_at` 升序, last element = newest。如果未来 R122+ 重排序成 desc, 这里要改 `[0]`。已在代码注释说明。
- **D-121-2: 单 score 显示而不是全部 evaluator 列表.** R118 #2 是 \"score badge\", 不是 \"score table\"。Run Info card 有限 vertical real estate, 一个 evaluator 的最近一次 score 是用户最常关心的。多 evaluator 详情仍在 RunList 的 Score 列 (R115 ship) 和 `chronos eval list <run-id>` CLI。
- **D-121-3: 数值 vs 布尔双渲染分支.** ADR-030 §43 的 `EvaluationResult` 允许 `score: float | None` 和 `passed: bool | None` 任一非空 — `output_length_chars` 出 score (数值), `final_state_key_present` 出 passed (布尔)。`scoreText` 优先 score (整数 `String(Math.trunc)` 或 `.toFixed(4)`), 退 boolean (`✓` 绿 / `✗` 红, `valueStyle.color` 染色)。
- **D-121-4: Failure 静默吞掉, 不挂树渲染.** Run Info card 显示 token / cost (R111 ADR-029) 是核心, evaluator 数据是 enhancement。R115 ADR-030 是新加的 endpoint, 老的 demo run 数据可能没数据 → 404 / 200-empty 都不该让 `<TreeView>` 整个崩。effect 里 `.catch(() => {})` 吞错误, score Statistic 不渲染, 别的功能照常。
- **D-121-5: i18n key 用 `tree.evalScore` 而不是 `node.evalScore` / `runInfo.evalScore`.** TreeView 的 i18n bucket 历史就叫 `tree.*` (treeShape / nodeCount / forkCount / etc.), 一致性优先。

### B. F14: doctor extras-warn Rich-markup escape regression fix (CLI, +25 LOC src + 44 LOC test)

#### 问题描述

`chronos doctor` 检查 `[web]` / `[langgraph]` / `[anthropic-agents]` / `[crewai]` / `[autogen]` 5 个 optional extras 是否安装。任一缺失时, output 是:
```
  ⚠️  Extra: [web]                 missing — pip install …
      Hint: `uv pip install 'chronos-agent[web]'`
```

可是 Rich 把 `[web]` 当成了 markup tag (像 `[bold]` / `[red]`), 由于 Rich 不认识这个 tag, 它**静默吃掉**了 — 不报错, 但渲染出来变成:
```
  ⚠️  Extra:                  missing — pip install …
      Hint: `uv pip install 'chronos-agent'`
```

`Extra:` label 后空着, hint 里的 install 命令变成 `'chronos-agent'` (extras 完全丢失) — 这是**给用户的 actionable hint 静默错误**, 用户复制粘贴照着跑 `uv pip install 'chronos-agent'` 没效果。

R110 原本的 `_escape_label` 已经处理 label 这一段 (R110 ship 时就遇到过 `Extra: [web]` 这个 label 的问题), 但只覆盖 label, 没覆盖 detail 和 hint。本轮 dogfood 推 F14 时实测 R120 baseline 的 doctor 输出在 cron container 里 `chronos doctor` 命令行确认了 hint 字段也被 Rich 吞了 — 这是 R110 的局部修复留下的 know-mode escape contamination。

#### 改动清单

- **`src/chronos/cli/doctor.py`** (+25 LOC, -2 LOC):
  - `_escape_label` 重命名为 `_escape_markup` (语义扩 generalised: 任何 user-facing 字符串 contain `[` 都得过这个), 旧名留作 backwards-compatible alias (R110 留下的旧测试可能 import 旧名, 不阻塞)。
  - `doctor_command` 渲染 loop 三处加 escape: label (旧 R110 已加 ✓), detail (新 — defensive, 当前代码字面值没 `[` 但未来扩 \"Extra path: [/path/to/file]\" 之类的 detail string 会踩坑), hint (新 — F14 主修)。
- **`tests/unit/test_cli_doctor.py`** (+44 LOC): 新加 `test_doctor_render_preserves_extras_in_hint`:
  - 用 `monkeypatch` 拦截 `importlib.import_module(\"fastapi\")` → `ImportError`, 模拟 web extra 缺失。
  - 创建空 SqliteStore (满足 schema check 不挂)。
  - 跑 `doctor_command`, 抓 console output。
  - 三个 assertion: (1) `\"Extra: [web]\"` 出现 (label 渲染对); (2) `\"chronos-agent[web]\"` 出现 (hint 渲染对 — F14 关键 invariant); (3) `\"chronos-agent'\"` **不**出现 (前缀闭引号但中间没 extras 是 broken pre-fix string, 看到了说明 `[web]` 又被吞了, 测试 fail)。

#### 设计决策

- **D-121-6: Widening `_escape_label` → `_escape_markup` 而不是新加 `_escape_hint`.** Rich markup `[` 是个 SSOT 问题: label / detail / hint 共享同一个 markup language, 同一个 escape 规则。新名字反映了 generalised role, 同 file 一处实现, 同时给老导入 alias 兼容。F14 修完后, 任何未来加进 `CheckRow` 的 user-facing 字段只要走 `_escape_markup` 都不会被 Rich 吃掉。
- **D-121-7: Test 用 `importlib.import_module` monkeypatch 而不是 mock 整个 `_check_optional_extras` 函数.** end-to-end 验证 — 真跑 `doctor_command` 全流程, 真渲染到 Rich console (用 `_capture_console` helper, R110 已有), 真 grep output。这样未来如果 `doctor_command` 重构, 测试还能 catch 这类 markup-eating regression。
- **D-121-8: 不动 `CheckRow` 数据 schema.** F14 只是渲染层的 escape bug, 不是 data model bug。`CheckRow.hint` 字段存的还是原始 `\`uv pip install 'chronos-agent[web]'\`` 字面值 (markup-friendly 的 raw form), 渲染时才 escape — 这样别的 consumer (JSON output, log adapter) 仍能拿到没污染的字符串。
