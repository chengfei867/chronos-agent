    What R108 ships (authored by prior slot, landed by this slot)¶

    Track A — --help docstring polish on all 11 verbs¶

    src/chronos/cli/__init__.py Typer command bodies now carry rich docstrings rendered as chronos <verb> --help. Each docstring has:

    1. A 1-paragraph summary of what the verb does + when to reach for it.
    2. An Example:: code block with realistic invocations (truncated UUIDs like 7c3f9e2a-...-a91, multiple flags shown).
    3. An Exit codes: table listing every typer.Exit(code=N) site the verb can hit, with a one-line operator action per row.

    Concretely, the 11 verbs (matching the R120 acceptance checklist):

    Verb Docstring shape Exit codes documented
    info summary + example (no exit codes — read-only)
    web summary + example 0 happy / 1 port-or-extra / 2 db-missing
    replay summary + 3-line example 0 happy / 1 run-missing / 2 db-missing
    runs list summary + 4-line example 0 happy / 2 db-missing
    runs show summary + 2-line example 0 happy / 1 run-missing / 2 db-missing
    forks show summary + 2-line example 0 happy / 1 fork-missing / 2 db-missing
    tree summary + 3-line example 0 happy / 1 run-missing / 2 db-missing
    diff summary + example (was rich before R108, exit-code table appended) 0 happy / 1 run-missing / 2 db-missing
    compare summary + example (was rich before, preserved) 0 happy / 1 run-missing / 2 db-missing
    fork plan summary + example 0 happy / 1 logical-error / 2 unknown-emit
    verify-golden summary + example (was rich before, preserved) 0 happy / 1 mismatch / 2 missing / 3 sanitiser

    R108 key decisions (logged for ratchet)¶

    • D-108-1: Single-commit single-slot for the entire R108 polish. CHANGELOG bullet + 11-verb docstring rewrite + 11 hint-line insertions + cli-reference.md rewrite + progress doc + CONTEXT §5/§6 — all logically one slice ("CLI Polish slice 1: documentation"). One commit, prefix docs(cli):, mirrors the v0.9.0 single-commit precedent (D-107-2).
    • D-108-2: Hint lines after, not replacing, the existing error. All existing tests assert on substrings like "no such run" or "no such fork". Replacing those phrases with hint-embedded variants would have broken ~6 tests and required re-ratcheting (R45-A risk). Appending a separate console.print after the error keeps the contract stable. Tests stayed at 666/9 with zero edits to test files.
    • D-108-3: Hint: styled with [dim] Rich tag. Operator gets a visual hierarchy — bold red error first, dim hint second. Matches the existing pattern used in chronos verify-golden for "secret detected" output. Pipe-friendly (Rich strips colour on non-TTY).
    • D-108-4: cli-reference.md is a doc, not auto-generated. Could have wired Typer's typer-cli to dump help text to markdown, but that would (a) introduce a new dev dep, (b) break the operator reading experience because Typer's auto-doc shape is verbose and un-grouped, and (c) lose the cross-references between verbs that the hand-curated doc has. The doc is short enough (~330 lines) that manual maintenance through R120 is cheap; if it grows past R120, revisit auto-gen as a post-1.0 dev-experience task.
    • D-108-5: Adapter zero-regression streak preserved. R108 didn't touch src/chronos/adapters/. Streak ratchets to R52→R108 = 56 rounds (NEW project-history high, +1 vs R107=55). Target at R120 = R52→R120 = 68 rounds.
