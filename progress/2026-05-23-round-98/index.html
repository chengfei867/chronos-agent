    Decisions¶

    • Stable GA, not alpha — Phase 5 Arc C is feature-complete (slices 1–5 all shipped), all gates clean, ready for stable cut. No skip-version concerns (no v0.8.x exists yet).
    • Created GitHub Release object explicitly via REST API rather than relying on tag-push side-effect. Per R88 finding, plain tag pushes do not auto-create Release objects; releases/latest keeps reporting the previous Release object. With make_latest=true, this round closes the gap so external consumers (PyPI mirroring, badge tools, "what's the latest?" scripts) see v0.8.0 immediately.
    • Atomicity: per R87 lesson, this progress doc was written ONLY AFTER push + verify both completed. No rollback needed.

    What worked / pitfalls avoided¶

    • chronos-release-pattern skill (validated 19× → now 20×) held the 8-step recipe perfectly; no deviations.
    • uv sync trap: After bumping pyproject.toml, uv run chronos --version and uv run pytest both timed out at 60 s and 300 s — uv was rebuilding the venv to match the new project version. Switched to uv run --no-sync and both completed instantly. (Adding pitfall to the skill in a follow-up patch.)
    • R88 anti-pattern avoided: did NOT skip the GitHub Release object creation; explicit POST to /repos/.../releases ensures releases/latest flips to v0.8.0 in the same round.
    • R87 anti-pattern avoided: progress doc written AFTER push + verify, not before.

    Skill update follow-up (R99 candidate)¶

    chronos-release-pattern skill should mention the uv run --no-sync pitfall: when the smoke re-verify step runs immediately after a pyproject.toml version bump, uv run triggers a venv re-sync that can hang the foreground command. Use --no-sync for the post-bump smoke gates since the source tree is unchanged.
