## R119 hand-off invariants (R119 prologue 用)

1. **Manifest is opt-in.** `_load_manifest` is fail-soft. New demos can ship without one (the loader will fall back to `DemoManifest.empty`). If R119 finds a corrupt manifest in production data, the fix is in `_load_manifest`'s except clause, not in callers.

2. **Evaluator hint priority is `recommended_evaluators[0]`.** R119 E2E should verify the printed eval command actually scores. If a demo lists an evaluator that's no longer registered (e.g. removed in v1.1), the CLI hint will print a stale name; R121 RC buffer can add a "evaluator name resolution at hint-render time" guard (low priority, not gating).

3. **`--list` output is rich-styled but no Box/Table.** Plain-TTY readability was prioritized. If R119 dogfood pass finds the listing hard to scan in a 80-col TTY (e.g. long descriptions wrap awkwardly), R121 can switch to `rich.Table` — it's a 20-line refactor.

4. **The 3 new demos use distinct UUID prefixes** (`aaaa…`, `bbbb…`, `cccc…`) and the original `builtin-minimal` uses `1111…`/`2222…`. R119 can rely on prefix-disambiguation across all 4 demos co-existing in the same DB — handy if dogfood pass wants to seed multiple demos into one DB to test multi-run RunList rendering.

5. **TreeView score badge (#2) + RunList tooltip relative-time (#4) + Demo GIF + mkdocs i18n** are all R121 RC buffer items. R119 should NOT touch them — R119 is read-only E2E walkthrough + finding catalogue. R120 RC1 cut should NOT touch them — R120 is tag-cut. R121 is the explicit polish slot.

6. **adapter zero-regression streak hit 67 this round.** R52→R118 = 67 consecutive rounds with `src/chronos/adapters/` byte-untouched. R122 acceptance requires ≥70. R119 + R120 + R121 + R122 = 4 more rounds → if all stay clean → **streak hits 71 at R122 ship**, which clears the gate. If any of those 4 rounds touches an adapter for a hard reason (real bug found in dogfood), the streak resets and we have to renegotiate the ≥70 number — flag to user.
