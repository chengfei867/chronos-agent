## Decision provenance (compressed)

- **D-111-1 — `--with-usage` becomes a deprecated no-op, not removed.**
  Alternatives: (a) hard-remove and break any user script — rejected,
  pre-1.0 still owes a deprecation cycle; (b) emit a stderr warning when
  passed — deferred to R116 doc-day if it actually causes confusion.
  Chosen: silent no-op + deprecation note in `--help`.
- **D-111-2 — Auto-hide columns on all-zero DBs (CLI and frontend).**
  ADR-029 §UX called for "always show", but on a fresh empty store every
  cell is `—` which is worse UX than no column. The "any run with usage
  → show" rule keeps the column when there's signal and hides it when
  there isn't. Same rule used in both CLI (`any_usage`) and frontend
  (`showUsage` memo) for consistency.
- **D-111-3 — JSON mode always emits `usage_summary` when computed.**
  Even when the table hides the columns, machine consumers (downstream
  tooling) need a stable shape — distinguishing "no usage recorded"
  (`nodes_with_usage: 0`) from "server didn't compute it" (field absent)
  matters for diff/compare logic.
- **D-111-4 — Single source of truth: `chronos.cli._usage._summarise_usage`.**
  The API server imports the helper rather than re-implementing it, so
  CLI and web stay in lockstep on token rounding / cost cell rendering.
  Light coupling (`api` → `cli._usage`) is acceptable per ADR-013 layering
  rules (CLI is the lowest-level operator-facing surface, API can depend
  on its helpers).
- **D-111-5 — Spike 20 covers the loader thread, not just storage.**
  The original `Node.usage` storage round-trip was already exercised in
  R45-era tests, but the *loader* (`quickstart_command` → `_build_node`)
  was silently dropping the field. Spike 20 catches that regression
  category by going end-to-end through the demo seeding path.
