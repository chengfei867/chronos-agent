## 3. 干了什么

### 3.1 App.tsx — Route union 扩展 + parseHash 扩展

- `Route` 的 `replay` variant 加了 `initialStep?: number` 字段 (optional, 不破坏现有 type narrowing)
- `parseStepParam(query: string): number | undefined` — 纯函数, 严格 `^-?\d+$` regex 过滤 (拒绝 `5.5`, `5e1`, 空白, `foo`); 通过后再 `Number.isInteger(n) && n >= 0` 二道关
- `parseHash` 用 `indexOf("?")` 切分 path 和 query, 复用 `parseStepParam` 提取 initialStep, 仅 `replay` route 接收
- export `parseStepParam` 给 r97-slice5-smoke.mjs 单独引用 (parseHash 自己依赖 `window.location` 不好测纯函数)
- App.tsx switch 的 `case "replay"` 改成传 `<Replay runId initialStep />`

`AppHeader.tsx` 的 `RouteName` union **不需要改** — slice 5 没引入新 route name, 只是给 `replay` variant 加了 optional 字段. R97 plan 已经预言了这个 sweep 不需要, 我 `grep -rn 'type Route\(Name\)\? = '` 确认了:

```

```

\"replay\" 已在, sweep 通过.

### 3.2 usePlayback — initialStep option

- 新加 `UsePlaybackOptions` interface: `{ initialStep?: number }`
- 函数签名 `usePlayback(totalSteps: number, options?: UsePlaybackOptions)` — options 可选, 现有 caller `usePlayback(total)` 不动
- `useState<number>(() => ...)` initializer 改成 lazy: 如果 `initialStep` 是有效整数且在 `[0, totalSteps)` 范围内, 用它; 否则 `-1` (\"not started\") 保持 R92 行为
- 重要: 这个 sync initialization 在 Replay.tsx 当前的数据流里 *几乎不会触发* — 因为 `total = 0` 第一次渲染时, `initialStep < total` 不可能. 所以又加了 Replay.tsx 那边的 post-load effect. 同步路径留着是为 (a) 将来如果 callers 同步知道 totalSteps 的话能少做一次 jumpTo, (b) 文档化 hook 的能力

### 3.3 Replay.tsx — initialStep + replaceState 双 effect

R97 plan §6 列出的 4 个边界 case 全部覆盖:

| Case | Replay.tsx 处理位置 | 行为 |
|---|---|---|
| `?step=5` 在 50-step run | post-load effect | jumpTo(5) ✅ |
| `?step=999` 在 50-step run | `Math.min(total - 1, ...)` | clamp 到 49 ✅ |
| `?step=-1` / `?step=foo` | App.parseStepParam | 在解析层 reject 成 `undefined`, Replay 走默认 `index = -1` ✅ |
| 用户翻到 step 12 | URL-sync effect | `replaceState` 写入 `?step=12` ✅ |

关键正确性 invariant: `replaceState` 而非 `pushState`. R97 plan §「单一非显然 correctness invariant」明确要求. 实现:

```tsx
useEffect(() => {
  if (index < 0) return;  // 不在 -1 状态下污染 URL
  const currentHash = window.location.hash;
  if (!currentHash.includes(`/runs/${runId}/replay`)) return;  // unmount 防御
  const desired = `#/runs/${runId}/replay?step=${index}`;
  if (currentHash === desired) return;  // 幂等, 防 React 18 strict mode 双调用
  window.history.replaceState(null, "", desired);
}, [index, runId]);
```

post-load seed effect 用 `seededRef` 守护单次执行 (`useRef(false)`), 避免数据 refetch 二次跳:

```tsx
const seededRef = useRef(false);
useEffect(() => {
  if (seededRef.current) return;
  if (total === 0) return;
  if (typeof initialStep !== "number") { seededRef.current = true; return; }
  const clamped = Math.max(0, Math.min(total - 1, Math.floor(initialStep)));
  jumpTo(clamped);
  seededRef.current = true;
}, [total, initialStep, jumpTo]);
```

## 4. 决策与判断 (没踩新坑, 但记几个微判断)

R97 没触发新的 failure mode. 几个微判断值得记:

**(a) F-1 — parseStepParam 是 pure parsing, NOT policy.** Out-of-range (例如 `?step=999`) 不在解析层 clamp, 而是在 Replay.tsx 用 `Math.min(total - 1, ...)` 在 callsite 处理. 理由: 解析层不知道 `total`, 强行 clamp 会把 \"明确指定的越界\" 跟 \"乱写一个数字\" 混淆. 让边界策略浮上去.

**(b) F-2 — 同步 hook initializer 在异步数据流下的局限性.** `useState(() => initialStep < totalSteps ? initialStep : -1)` 看起来漂亮但其实首次渲染 `total = 0` 永远不满足. Replay.tsx 必须额外加 post-load effect 兜住. 留着 hook 里的 sync path 是给以后 SSR / 同步 cache hit 场景做铺垫, 不是 dead code.

**(c) F-3 — `replaceState` 幂等防御.** React 18 strict mode 在 dev 下会双调 effect, 加 `if (currentHash === desired) return;` 防止 dev console 满屏 history-state 噪声. Production behavior 不变, 但 dev experience 提升.

**(d) F-4 — i18n 0 key 是合规的.** R96 F-2 教训本轮被预言式应用: slice 5 完全 invisible to user (URL update 是地址栏行为), 不加 i18n key 是正确的. R97 plan §7 已经写明 \"OPTIONAL — 只在加 'copy URL' 按钮时才需要\", 没加按钮就不加 key.
