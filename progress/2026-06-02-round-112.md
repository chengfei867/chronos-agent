## What shipped (3 fixes — 2 P0s + 1 P1, per the dogfood report)

**P0 #1 — `NodeDetails` Total-Tokens cell renders `–` even when usage exists**:
- New `frontend/src/format/usage.ts` (~50 LOC) — 5 helpers (`totalTokens`,
  `formatTokensCompact`, `formatCostUsd`, `formatTokenDelta`, `formatCostDelta`).
  `totalTokens()` is best-effort: prefers `usage.total_tokens` if numeric,
  else falls back to `(prompt ?? 0) + (completion ?? 0)` when ≥1 component
  is populated, else `null`. `formatCostUsd(cents)` is the single source
  of truth for `$X.XXXX` rendering (matches CLI `_RunUsageSummary.cost_cell`).
- `NodeDetails.tsx`: import the helpers, swap inline rendering for them.
  Before: `node.usage.total_tokens ?? "–"` shows `–` for adapter-recorded
  nodes lacking explicit total. After: shows `200` for the demo parent
  draft node (= 120 prompt + 80 completion).

**P0 #2 — `.chr-diff-page` height collapses to 0px → ReactFlow blank**:
- `styles.css`: `height: 100%` → `height: calc(100vh - 56px - 48px - 48px)`,
  matching `.chr-tree-page`'s already-correct viewport math. Comment
  updated to spell out the `AnimatePresence` wrapper detail and tagged
  `R112 P0 #2 fix`.

**P1 — Landing Step Cards animate inconsistently on initial load**:
- `Landing.tsx`: Step-card row's Framer-Motion spec changed from
  `whileInView={{...}} viewport={{once:true, margin:"-10% 0px"}}` to
  plain `animate={{opacity:1, y:0}}`. Since the cards are above the
  fold, `whileInView` was unreliable on initial mount. Other Landing
  sections that ARE below the fold keep `whileInView` (correct for them).

## Decision provenance (compressed)

- **D-112-1 — Adopt inherited WIP, do not redo or revert.** The inherited
  3-file diff was clearly R112-flavored (comments self-tagged), gates
  passed unchanged, and each hunk maps 1:1 to a real P0/P1 the round
  was meant to surface. Reverting would have wasted prior-slot work
  and pushed the same fixes into R113 anyway. Per `cron-slot-handoff-recovery`
  Option A2 + A1 rules, audit + adopt + close-out is the correct path.
- **D-112-2 — Defer the live-browser dogfood pass to R113.** The slot
  budget was largely consumed by recovery diagnostics + the dogfood
  report write-up + the close-out (CHANGELOG + CONTEXT §5/§6 + this
  doc + commit + push). Spinning up `chronos web` + Vite dev + browser
  vision tool + screenshot capture was estimated at 15-20 tool calls,
  which combined with close-out floor (~10) would risk an iteration-cap-out
  per `cron-slot-handoff-recovery` rule 2. Deferral is documented in
  the dogfood report's R113 hand-off section so the next slot picks up
  cleanly.
- **D-112-3 — Single source of truth for token/cost rendering: the new
  `format/usage.ts` module.** The CLI side already has
  `chronos.cli._usage._summarise_usage` as its SSOT (D-111-4). The
  frontend was duplicating the rendering logic inline in NodeDetails
  (`(cents/100).toFixed(4)`) and in RunList (a different inline rule
  that uses sub-cent precision when needed). The new module gives
  front + back parity AND lets RunList migrate to the same helpers
  in R113 if the dogfood finds drift. Light refactor risk: tested via
  `tsc --noEmit` + `vite build`; no runtime tests in the frontend
  suite to protect this surface, so manual visual verification is
  R113's job.
- **D-112-4 — `totalTokens()` falls back to summing components rather
  than returning null when total_tokens is missing.** The chronos
  `Usage` model has all 3 fields optional. Several adapters
  (LangGraph in-process capture, AutoGen) historically record only
  prompt+completion. Showing `–` when the user can see non-zero
  prompt + completion is worse UX than computing the sum client-side.
  Returns null only when ALL three are null (i.e. zero signal).
- **D-112-5 — Diff-page height fix uses the same constants as
  `.chr-tree-page` (56+48+48 = 152px subtracted from 100vh) rather
  than introducing a CSS variable.** Two pages, two literal copies
  of the same constant — DRY argues for a variable, but the existing
  `.chr-tree-page` rule has been stable since R39-A and adding a
  variable in R112 would force a touch on `.chr-tree-page` too,
  expanding the diff for no functional gain. Defer to R113-R114
  if the dogfood finds a third page that needs it.
