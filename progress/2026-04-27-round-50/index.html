    1. Why this round¶

    CONTEXT.md §6 laid out R50 with two must-dos:

    1. Screenshot refresh of all three fork-modal PNGs against post-R48-B code so the docs truthfully show the effect-tag badge icons (which are the whole point of R48-B's UX polish). R47-A captures were shot against pre-R48-B plain-text-tag rendering and therefore looked out of sync with shipped v0.4.0a2.
    2. LangGraph docstring patch documenting the kind_map silent-safety pitfall R49 surfaced in spike11_langgraph_tool_effects.py: un-mapped nodes → NodeKind.FN → classifier TOOL-gate → effects=[] → green "safe" modal on an actually-dangerous run. Loud false-alarm is annoying; silent false-safety is a fork-time footgun.

    Both items are strictly docs-or-docstring — the riskiest work in R50 was the browser capture flow, which the pre-existing chronos-docs-screenshots skill already documented down to "hide the Drawer with a CSS override before screenshotting the Modal".

    2. What landed¶

    2.1 LangGraph docstring warning (<20-line change)¶

    src/chronos/adapters/langgraph.py — inserted after the kind_map Args entry on the LangGraphRecorder class docstring:

    .. warning::
    **Pass ``kind_map`` for any node that performs I/O** (network calls,
    filesystem writes, database access, external subprocess) if you rely
    on Phase 3 fork-plan *effect annotations* (the dangerous-effect
    warnings shown in the Web fork modal and CLI ``fork-plan``).

    LangGraph adapters have no reliable way to infer a node's kind from
    the graph alone, so un-mapped nodes fall back to
    :attr:`NodeKind.FN`. The effects classifier's TOOL-gate then
    short-circuits those nodes to ``effects=[]``, which looks like
    *safe-to-fork* in the UI — even if the node actually hits the
    network. This is silent false-safety, which is strictly worse than
    a loud false-alarm.

    Explicitly mark I/O-doing nodes as :attr:`NodeKind.TOOL` in
    ``kind_map`` to opt them into effect annotation. See
    ``docs/research/r49-langgraph-adr020-audit.md`` for an empirical
    walkthrough (spike 11).

    First draft also mentioned NodeKind.IO as an alternative — caught myself pre-commit (IO does not exist; only LLM/TOOL/FN/ROUTER/FORK/END). Trimmed to NodeKind.TOOL only. Lesson noted for future adapter docs: verify enum surface before citing it, even in a docstring.

    2.2 Fork-modal screenshot recipe (3 PNGs, all R48-B-styled)¶

    Used the chronos-docs-screenshots skill's "Fork Modal Screenshot Recipe" section verbatim:

    1. uv run python scripts/seed_r47a_effects.py --db /tmp/chronos-r50.db → three runs (warn / safe / lastnode).
    2. uv run chronos web --db /tmp/chronos-r50.db --no-browser --port 8765 in a watched background process. curl /healthz confirmed boot.
    3. For each scenario: browser_navigate to the run URL, close the Tour on first visit, click the target node's inner generic (NOT the group ref), click "Fork here" in the Drawer, wait ~1.5 s, then inject document.querySelectorAll('.ant-drawer').forEach(d => d.style.display='none') to hide the Drawer behind the Modal.
    4. browser_vision for one final QA pass, then copy the cached screenshot into docs/images/fork-modal/.
    # Scenario Run Node Alert colour Effect-tag icons rendered?
    01 Warning run_25b301997e6f (warn) step 0 plan_agent Amber / warning ✅ 4 badges (db / network / fs / external) with lucide icons
    02 Safe — pure LLM run_3fc9ecfa7954 (safe) step 0 plan Green / success ✅ (trivially — zero dangerous tags, so zero badges is the point)
    03 Safe — last node run_9265693398c2 (lastnode) step 1 answer Green / success ✅ (trivially — zero downstream)

    All three PNGs are 104–109 KB (same range as the R47-A captures, which implies comparable visual density — reassuring).

    2.3 Gotcha encountered (browser session reset mid-capture)¶

    After capturing 01 and 02, the agent context window compacted and the browser_* session came back as about:blank. Re-navigating to run 3 re-triggered the first-visit Tour even though the earlier captures had dismissed it — so the Tour is session-scoped, not localStorage-scoped. Noted below in §6 (skill-patch candidate) — not fatal, but a useful breadcrumb for future cron-slot screenshot work.
