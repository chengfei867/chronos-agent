## What shipped

### 1. `scripts/capture/capture_anthropic_agents.py` (~360 LOC)

CLI:

```
uv run python scripts/capture/capture_anthropic_agents.py \
  --db <recorded.db> --run-id <UUID> --out-dir <dir> [--force]
```

- Exit 0 on success, 1 on runtime error / unknown run-id, 2 on missing
  DB file.
- Loads `Run + Nodes` via `SqliteStore.open(...)` →
  `get_run(run_id)` + `get_nodes_for_run(run_id)` (same API spike 19
  proves correct).
- Aborts if `Run.adapter != "anthropic_agents"` — the driver is
  recorder-specific by design (slot-3 R102+ ships sibling drivers
  for langgraph/crewai/autogen).
- Aborts if `len(nodes) == 0` (nothing to capture).
- Refuses to overwrite a populated `out-dir` unless `--force` is set.
- Per envelope: build `StreamEvent`-shaped dict from each Node, then
  `json.dumps(canonicalise(env), …)` → `sanitise_capture(line)` →
  write to `envelopes.jsonl`.
- For `expected_run.json`: `golden_dumps(project_to_golden(run, nodes))`
  with the same canonicalisation, then `sanitise_capture()` belt.

## Decisions taken (no ADR amendment needed — within ADR-028 scope)

### D1. Duplicate-by-copy, not import-from-spike

ADR-028 §4 leaves slot-2 hoisting (`tests/spikes/spike19_*.py` →
`src/chronos/golden/{projection,sanitise}.py`) as Option A. R101 chose
to **duplicate the helpers by-copy** in the capture driver rather than
import them from `tests/spikes/`. Reasons:

1. `tests/spikes/` is not on `sys.path` for production imports — only
   pytest mounts it. A `scripts/capture/*.py` driver would need
   `sys.path` manipulation to import a spike, which is ugly.
2. The spike's only top-level work is appending its parent to
   `sys.path` (for its own helper imports). Importing the spike would
   re-run that side-effect.
3. Hoisting the helpers out of the spike to `src/` is itself an Arc-D
   slice (the eventual R102 slot-2 Option A). Doing it now would
   conflate two unrelated changes in one round.

The risk of duplication (silent drift) is mitigated by three pin tests
(#4, #5, #8 above) that load the spike via `importlib` and assert
byte-for-byte output parity. Drift is therefore impossible — the test
suite will fail on any divergence. R102 is the natural moment to
collapse both copies into `src/chronos/golden/`.

### D2. Sanitiser belt at write-time, not at projection time

The sanitiser runs on the **JSON-serialised line** (string form), not
on the dict before serialisation. This is intentional: regex patterns
designed for HTTP / config / log shapes are most reliable against the
exact string form an attacker would scan for. The recorder also redacts
at record-time, so this is purely defence-in-depth — exactly the
"belt + braces" stance ADR-028 §3 requires.

### D3. CLI surface stays thin

No `--scenario` flag, no automatic `out-dir` discovery from a config
file — the driver takes raw `--db / --run-id / --out-dir` and lets a
shell wrapper or human compose the right `tests/golden/<adapter>/<scen>`
path. R102+ may layer a `chronos verify-golden` CLI verb on top
(per ADR-028 slice 3 and R100 close-out plan), but that's a separate
slice.
