### Spike 19 — three invariants

| invariant | what it proves | result |
|-----------|----------------|--------|
| **INV-1** round-trip byte-equality | Synthetic 3-envelope Run (agent_start/llm/agent_end) → real `SqliteStore` (no mocks, per spike-18 precedent) → re-fetch → `project_to_golden` → `golden_dumps` → byte-equal to pre-committed 595-byte `expected_run.json`. ## Decisions

1. **Stripped fields list at v0.** `Run.id`, all timestamps, `Node.id`, `Node.usage`, `Node.cost_usd_cents`, `tool_input`, `tool_output`, `Run.adapter_thread_id`, `Run.tags`, `Run.metadata` are all excluded from the projection. Each had a forcing reason: UUIDs are non-deterministic, timestamps are wall-clock, usage/cost vary per relay run, tool_input/output are large and the canonical projection for them needs a separate design pass (deferred to v1 / ADR-028 amendment), and the meta fields aren't behaviour. The risk: the `tool_input/output` deferral means spike 19 doesn't yet prove tool determinism. ADR-028 §8 explicitly accepts this — slice 1 is the *envelope-and-state-shape* contract, not a full behaviour-equivalence proof. Slice 2 (R101+) lifts seed-adapter capture and forces this question.

2. **Inline ref impls in the spike, hoist to `src/chronos/golden/` at R102.** Tempting to start the package layout now (one-line `from chronos.golden import project_to_golden`), but ADR-028 §4 holds the line: package layout drops with the CLI verb at slice 3. Premature package-creation invites scope creep into the data-contract slice. The `chronos-adr-layout-drift` skill warns against exactly this — package layout is in the ADR, not the spike round.

3. **Pytest collection: deliberately NOT.** Same rationale as spikes 16/17/18: spikes are *disprovers*, runnable as `__main__` with explicit pass/fail prints, and become regression-gating only via downstream pytest wrappers. CI-gating spike 19 at R100 would couple the data-contract probe to the CI lifecycle prematurely.

4. **Sanitiser pattern set: minimal but adequate.** Five patterns. Could add: GitLab personal access tokens (`glpat-…`), GitHub PATs (`ghp_…`), Slack bot tokens (`xoxb-…`), GCP service-account private-key blocks. Decision: hold for slice 2 — the pattern set should grow with **observed** real fixture leakage attempts, not speculative additions. The contract doc §5 explicitly authorises growing the set without a v-bump; that's the safety valve.

5. **No browser/UI work this slot.** ADR-027 §3 sibling rule was satisfied by Arc D's data-contract nature: there's no client-side render budget here, no perf gate that needs `browser_vision`. R100 is a pure-Python slot. R101 won't add UI either; UI returns at R102 if `chronos verify-golden` grows a frontend tree-view (likely not — it's a CLI verb).

## Findings

- **F-1.** `Run.task_description` is `str | None` per the model; the projection emits `null` for None. Edge case validated: the synthetic Run sets `task_description="spike19 synthetic 3-envelope round-trip"` so the byte-target file has a non-null value. INV-1 will catch a stray `or ""` defaulting if anyone adds it.
- **F-2.** `dict.__iter__` insertion order is stable in Py 3.7+, but I added explicit `_canonicalise()` recursion + `sort_keys=True` at serialise time anyway — defence in depth. The 1-second sleep in INV-2(a) is a lightweight clock-leakage probe; it's the only deliberately slow assertion in the spike.
- **F-3.** Sanitiser regex for OpenAI keys uses negative-lookahead `(?!ant-)` so it doesn't double-redact Anthropic keys. Pattern order in `_SECRET_PATTERNS` doesn't actually matter today (no overlapping matches), but the lookahead makes the patterns commutative defensively.
- **F-4.** `SqliteStore.put_node` requires the parent run to exist (FK constraint). The spike's `_build_synthetic_run` returns Run + nodes together, and the round-trip helper puts the Run *before* the nodes — pattern matches spike 18's precedent.
