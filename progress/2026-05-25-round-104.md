## What shipped

### Track A — `chronos verify-golden` CLI verb (the headline)

A single new module `src/chronos/cli/verify_golden.py` (~165 LOC inc. docstring) implementing the operator-facing read side of the ADR-028 golden-trace contract. The verb takes a recorded `Run` (in a `chronos.db`) plus a directory of golden-trace fixtures (`tests/golden/<adapter>/<scenario>/`) and asserts two independent invariants:

1. **Projection byte-equality** — load `Run` + `Nodes` from SQLite, project via `chronos.golden.project_to_golden` + serialise via `golden_dumps`, byte-compare against `<golden-dir>/expected_run.json`. Mismatch → unified diff printed to stdout, exit 1.
2. **Suspenders sanitiser audit** — read `<golden-dir>/envelopes.jsonl` raw, run each `_SECRET_PATTERNS[i].rx.search()` against the text. First match → exit 3, the matched pattern's name (e.g. `ANTHROPIC_KEY`) is reported so the operator knows which capture-time rule to investigate. The audit runs **before** the byte-compare so a fixture that leaked a secret + happens to project byte-equal still fails loudly.

**Exit-code contract** (4 rows, pinned by tests):

| Exit | Meaning |
|------|---------|
| 0 | byte-equal AND sanitiser-clean |
| 1 | projection mismatch (unified diff to stdout) |
| 2 | missing `--golden-dir`, missing `expected_run.json`, missing `envelopes.jsonl`, OR unknown run id |
| 3 | secret pattern hit in `envelopes.jsonl` (re-record needed) |

The constants `EXIT_OK / EXIT_MISMATCH / EXIT_MISSING_FIXTURE / EXIT_SANITISER_HIT` are module-level so the test suite can pin the contract without magic numbers.

**Key design decisions:**

- `D-104-1`: **Run audit before byte-compare**. The audit is the more critical gate — a leaked-secret fixture that happens to project byte-equal must NOT slip through. Byte-compare is cheap; we want loud refusal on any sanitiser hit, regardless of projection state. Gate ordering: missing-fixture → audit → store-open → project → compare.
- `D-104-2`: **`re.search()`, not `sub()`+compare**. The R101 capture driver applies `sanitise_capture` (which redacts via `sub`); the verifier's job is to *detect and refuse*, not *fix up*. Using `search()` directly surfaces the matched pattern's name back to the operator — they can then triage whether the capture-time belt-layer has a pattern miss, or whether the fixture was hand-edited post-capture. Redacting at load would silently turn a leaky fixture into a passing one — exactly the regression net's anti-goal.
- `D-104-3`: **Unknown run id reuses exit code 2** (missing-fixture family). Same operator action — re-record / pick a real run id, point at `scripts/capture/`. Adding a 5th exit code "unknown run" was rejected as cosmetic; the error message is unambiguous enough.
- `D-104-4`: **Typer wiring, NOT argparse** as the R103 plan specified. The R104 plan (CONTEXT.md §6) said "argparse tree", but the existing CLI has been Typer-based since R14 (every existing subcommand: `runs list/show`, `forks show`, `diff`, `replay`, `tree`, `compare`, `fork plan`, `web`). Mixing argparse mid-tree would break the established pattern and break `chronos --help` cohesion. The Typer wrapper mirrors `chronos replay`'s shape exactly (thin Typer command in `__init__.py` → `*_command(...)` function in module file). This is a documentation-of-record correction, not a scope change — the plan's *substance* (CLI subcommand wired into the `chronos` tree, exit codes, suspenders gate) is unchanged.
- `D-104-5`: **Unified diff goes to plain `print()`, not Rich console**. Pipe-friendly: `chronos verify-golden ... | head` won't get truncated by Rich's terminal-width wrapping. The status line ("mismatch: ...") still goes through Rich for the operator-facing colour cue.

**Module layout:**

```
src/chronos/cli/verify_golden.py
├─ EXIT_OK / EXIT_MISMATCH / EXIT_MISSING_FIXTURE / EXIT_SANITISER_HIT  (constants)
├─ _scan_for_secrets(envelopes_text) -> str | None                      (pure)
└─ verify_golden_command(db, run_id, golden_dir, open_store_fn, console) -> int
```

The `open_store_fn` injection mirrors `replay_command` / `runs_*_command` so tests can pass a fake without recreating the SqliteStore — same plumbing pattern as the rest of `src/chronos/cli/`.

### Track B — Tests

`tests/unit/test_cli_verify_golden.py` — 4 tests, one per exit code:

1. `test_verify_golden_happy_path_returns_0`: in-memory SqliteStore + tmp golden dir whose `expected_run.json` is generated by the same `project_to_golden` + `golden_dumps` the verifier uses. Asserts `code == EXIT_OK` + "ok:" in console output.
2. `test_verify_golden_mismatch_returns_1`: same baseline, then tamper `expected_run.json` (s/r104 verify-golden round-trip/tampered-by-test/). Asserts `code == EXIT_MISMATCH` + the unified diff (captured via `capsys`) contains both old and new strings.
3. `test_verify_golden_missing_fixture_returns_2`: point `--golden-dir` at a non-existent path. Asserts `code == EXIT_MISSING_FIXTURE` + "golden-dir not found" + "scripts/capture/" in console output.
4. `test_verify_golden_sanitiser_hit_returns_3`: append a synthetic `sk-ant-api03-FAKE0000fakeFAKE0000fakeFAKE0000fake` line to `envelopes.jsonl` (matches `_SECRET_PATTERNS[0]` `ANTHROPIC_KEY`). Asserts `code == EXIT_SANITISER_HIT` + "ANTHROPIC_KEY" + "re-record" in console output.

All 4 use the same `synthetic_run_and_nodes` + `populated_store` + `golden_dir_with_matching_fixture` fixture chain — keeps test bodies focused on the contract row each one pins. The synthetic run uses run id `00000000-0000-0000-0000-0000000000a4` so it doesn't collide with R101's `…001` test run id.
