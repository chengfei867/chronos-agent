## 3 · Decisions

### D-107-1 — phase-token assertion uses `or`, not pinned

`test_cli_info` previously hard-pinned `phase 4`. The R107 status line carries BOTH `phase 5` AND `phase 6` (the boundary line). Pinning either one alone would re-trip in 1-2 rounds when R108 ratchets the line. Used `phase 5 OR phase 6` so the assertion stays green through the entire R107-R120 Phase 6 RC arc. R45-A's general fix shape (assert on stable tokens, not exact strings) honoured.

### D-107-2 — single-commit release per existing pattern

CHANGELOG roll + 3-file version bump + uv.lock + 1 test fix + progress doc + CONTEXT.md §5/§6 = one logical commit. Mirrors v0.7.0 (R87) and v0.8.0 (R98) precedent. Conventional message: `release: v0.9.0 — Phase 5 Arc D close-out + Phase 6 RC kickoff`.

### D-107-3 — preamble explicitly cross-references `docs/r120-acceptance.md`

CHANGELOG `[0.9.0]` header preamble names the user-mandated R120 contract by file path, so future agents reading CHANGELOG alone (e.g. on the GitHub Release page) see the Phase 6 charter is *user-authorised*, not agent-improvised. Reduces "is this drift?" questions in R108-R120 close-outs.

### D-107-4 — no ADR for the Phase 5 → Phase 6 boundary

Phase boundaries are CONTEXT.md / CHANGELOG / progress-doc artefacts; they don't require an ADR per the project's ADR-discipline (ADRs are for technical decisions, not roadmap milestones). The Phase 6 charter lives entirely in `docs/r120-acceptance.md` (user-authored / agent-extended) and CONTEXT.md §5. No new file needed.

### D-107-5 — `verify-golden` added to the `info()` verb list

R106 closed Phase 5 Arc D feature work; R104's `chronos verify-golden` is the user-facing surface and should appear in the front-page CLI verb listing. Other R104-shipped strings (the verifier's exit-code contract) are in `docs/contracts/golden-trace-format.md` §6 — no need to surface every detail in `info()`.

## 6 · R108 plan (Phase 6 Track 1 slice 1 — CLI help/error 文案 polish)

Per `docs/r120-acceptance.md` Phase 6 Track 1 R108:

1. Walk every Typer command in `src/chronos/cli/__init__.py` + `src/chronos/cli/*.py` (11 verbs total: `info`, `web`, `runs list/show`, `forks show`, `diff`, `replay`, `tree`, `compare`, `fork plan`, `verify-golden`).
2. For each: rewrite the docstring (Typer reads it as `--help` body) so it includes:
   - One-line summary (already exists).
   - **Example** code block showing a real invocation with a real-looking arg (e.g. `chronos replay 7c3f...a91 --step 3`).
   - **Exit codes** table when the verb has a non-trivial contract (verify-golden has 4 rows, replay/diff have 2-3).
3. For each error path that surfaces to the user (`typer.Exit(...)` raises with a Rich-printed message), audit for actionable hint:
   - Bad: `Run not found: 'abc'`.
   - Good: `Run not found: 'abc'. Hint: list available runs with 'chronos runs list'.`
4. New file `docs/cli-reference.md`: documents all 11 verbs (placeholder sections for `quickstart` and `doctor` which are R109/R110).
5. **No new functionality** — pure docstring + error-text + reference-md edits.
6. Single commit, single slot. Tests: existing test suite must still pass; no new tests required (docstring changes don't need test coverage). Add ≤2 tests if any error path's text is sufficiently structured to deserve a regression pin (e.g. "the actionable hint mentions `chronos runs list`").
